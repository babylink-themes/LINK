# 情侣守护使用说明

## 这是什么

情侣守护是单个角色 `LifeLedger` 的授权镜像，不是独立的人生生成器，也不是监控工具。

每个角色只有一条持续追加的生活账本：它只记录用户尚未从当前私聊、用户所在群聊、VOOM、通话、消息送达或已读状态中得知的角色生活事实。情侣守护只是在双方授权后，为当前单聊提供一种更适合查看这条未知生活历史的情侣 App 界面。

所有数据仅保存到当前设备的 IndexedDB，以及用户主动创建的备份中。

## 开始使用

1. 进入角色的线上单聊，打开“情侣守护”。
2. 首次使用时阅读说明，勾选“双方自愿开启的互动模拟”，然后点击“进入我们的空间”。
3. 授权完成后，点击“写下今天的第一页”或“更新此刻”。应用会调用已配置的全局内容创作模型，建立或推进该角色的 `LifeLedger`。
4. 生成成功后，可以在弹窗底部切换“今天”“足迹”“手机”：
   - **今天**：查看当前地点、状态、心情，以及按时间倒序排列的最近 24 小时生活日记。点击任一条可展开该事件的完整原始记录。
   - **足迹**：查看模型本次状态中可用的 24 小时行程节点、停留内容与同行信息。
   - **手机**：查看角色世界内的当前手机状态、备忘录、日程和生活记录。
5. 右上角菜单打开“只属于我们的设置”，可开启或关闭整个情侣守护功能，或经确认清空该角色的守护账本、快照、心愿与聊天守护卡片；共享授权与开关会保留。

情侣守护只保留最近 24 小时的数据。账本事件、快照、心愿、旧版 `coupleSpace.life` 记录和聊天守护卡片一旦超过窗口都会从当前设备的 IndexedDB 删除；不会进入展示、角色回复上下文或内容模型输入。聊天菜单的“清空记忆”会立即一并清空情侣守护全部历史，但共享授权与开关仍会保留。

## 情侣守护总开关

“开启情侣守护”控制该角色的整个情侣守护功能：

- **开启**：角色可在合适剧情中选择 `life_ledger.advance`，手动“更新此刻”可请求内容模型，新产生的允许投影事件会追加到当前聊天。
- **关闭**：不会请求情侣守护内容模型、不会向角色提供 `life_ledger.advance`、不会写入新的守护账本事件，也不会新增聊天守护动态。已有账本和授权会保留在当前设备，但只显示为暂停状态。

重新开启后不会补写关闭期间的内容；仅从下一次手动更新或角色主动选择工具时继续生成。

## 隐私与内容边界

- 情侣守护是角色世界内的互动模拟，不会读取真实 GPS、系统解锁记录、后台应用、真实联系人或真实手机文件。
- 当前私聊、用户所在群聊、VOOM、通话、消息送达与已读状态都不会写入账本、手机镜像、行程或生活日记；正常聊天上下文本身已经保存这些事实。
- 守护日记、聊天动态与回复上下文只使用 `life-advance` 与 `system` 来源的未知生活事件；旧账本中的已知互动不会删除或改写，只是不在这些守护表面重复展示。
- 单条守护动态只对应一条账本事件；展开后显示该事件的真实模型输出区块，不会把其他事件拼接进去。

## 内容模型 API 调用逻辑

### 1. 前置条件

情侣守护使用设置页中已配置的**全局内容创作模型**。模型设置采用 OpenAI 兼容接口：

- `API Url`：供应商根地址。
- `API 路径`：通常是 `/chat/completions`。
- `API Key`：以 Bearer Token 方式发送。
- `Model`：全局内容创作模型。

未配置模型时，手动更新会提示配置要求；不会生成本地示例、假记录或降级内容。

### 2. 哪些操作会调用 API

| 操作 | 调用次数 | 说明 |
| --- | --- | --- |
| 打开情侣守护弹窗 | 0 | 只读取本地账本和授权状态。 |
| 切换“今天 / 足迹 / 手机” | 0 | 只切换本地展示。 |
| 展开单条生活日记 | 0 | 只显示该事件已保存的原始详情。 |
| 切换情侣守护总开关 | 0 | 只保存开关状态；关闭后阻止后续守护 API 请求与账本写入。 |
| 点击“写下今天的第一页”或“更新此刻” | 1 | 用户手动请求一次角色生活账本推进。 |
| 私聊角色回复时选择 `life_ledger.advance` | 最多 1 | 仅线上一对一聊天。角色根据当前剧情自行决定是否调用；调用会在最终回复前完成并回填真实保存结果。 |
| 群聊回复、生成 VOOM、通话 | 0 | 这些用户可见表面不会读写情侣守护账本，也不会自动调用情侣守护内容模型。 |
| 其他聊天、群聊、VOOM、通话事件 | 0 | 消息、已读、VOOM 或通话状态只保留在各自表面，不会追加到情侣守护账本。 |

### 2.1 角色可选工具判断

线上一对一回复只会在情侣守护已授权、总开关开启且全局内容创作模型已配置时，向角色提供内建 `life_ledger.advance` 工具。它不是外部 MCP 服务，不需要配置服务器、授权或额外网络权限。角色可以调用，也可以不调用；每次回复最多调用一次。

角色应在自然出现未知生活变化时优先调用，不必等到戏剧性的转折：时间自然流逝、地点或交通变化、开始或结束持续活动、外部安排、设备状态变化、会影响后续行动的承诺或关系下一步，都是合理时机。

普通寒暄、短消息、重复情绪、仅阅读或发送当前聊天消息、没有实际状态变化的互动、用户已经知道的内容，以及为了丰富剧情而虚构的内容都不应调用。工具调用对用户不可见；模型不能提到账本、工具、系统或监控。工具失败时，最终回复不能把未保存的生活内容说成既成事实。

“写下今天的第一页”“更新此刻”只在总开关开启时直接请求一次推进；打开守护、切换页面、查看详情、切换总开关均不会调用 API。

### 2.2 不进入账本的已知表面

用户已经能看到的内容不需要在情侣守护重复保存。当前私聊、用户所在群聊、VOOM、通话、消息收发与已读只保留在原本的聊天或动态表面：它们不写入 `LifeLedger`，不改变守护手机镜像，也不会成为模型生成守护事实的来源。旧版本中留下的同类账本事件会在加载时过滤。

### 3. 一次手动更新的流程

手动更新由弹窗调用 `refreshCoupleSpace(conversationId)`，再进入 `advanceCharacterLife()`。角色可选调用时，当前回复模型先输出受限参数 `reason`、`trigger` 与 `contextHint`；Store 再进入同一条 `advanceCharacterLife()` 途径。两种方式都遵循以下流程：

1. Store 确认这是线上会话、当前角色没有同一时间的重复请求，并确认全局内容创作模型已配置。
2. `generateLifeLedgerAdvance()` 组合角色设定、绑定用户、最近 24 小时的可见聊天上下文、世界书、会话摘要、记忆上下文、当前时间、已有账本快照和最近 24 小时的未知生活事件。当前聊天上下文只用于避免重复生成用户已知内容，不能被写回账本。可选工具的受限参数只作为剧情线索，不能替代上述事实来源。
3. `callTextApi()` 向配置的 OpenAI 兼容模型发送请求。开发环境会优先通过同源代理转发，避免浏览器跨域限制。
4. 模型必须返回合法 JSON，包含推进后的 `snapshot` 和本次新增 `events`。
5. `assertCompleteLifeLedgerEventPayload()` 在任何数据写入前校验每个事件具有标题、摘要与可读完整经过。`detailBlocks` 是可选的模型原始详情：模型提供时会校验其结构和内容，未提供时不会填充或凭空补写。
6. 校验通过后，数据才会规范化、去重并追加到角色的唯一 `LifeLedger`，随后通过角色快照写入 IndexedDB。可选工具成功后，已保存的快照和事件摘要会回填给同一轮角色回复模型。
7. 总开关开启时，符合可见性规则的新增事件才会投影为当前聊天的守护楼层。

### 4. 失败时的行为

以下情况会直接显示错误，且不会写入本地替代内容：

- 未配置内容创作模型、模型请求失败、网络失败、鉴权失败或 API 返回为空。
- API 返回的内容不是合法 JSON。
- 缺少 `events`、标题、摘要或完整经过。
- 模型提供的详情区块包含未知类型或不完整字段。

应用不会为模型补写“默认生活动态”“通话概览”“主要内容”或其他固定文案，也不会截断已通过校验并保存的事件正文、详情区块、逐条对话或字段值。

## 数据结构概览

```text
CharacterProfile
└─ lifeLedger
   ├─ current                 当前生活／手机快照
   ├─ events[]                只追加、不重写的生活事件
   ├─ lastAdvancedAt          最近一次推进时间
   └─ contentAdvanceCount     内容模型推进次数

CharacterProfile
└─ coupleSpace
   ├─ consentGrantedAt        授权时间
   └─ enabled                 情侣守护总开关
```

`coupleSpace` 保存授权与总开关；真实的连续生活事实始终以 `lifeLedger` 为唯一来源。

## 常见问题

**为什么打开后没有内容？**

首次授权只建立查看权限。点击“写下今天的第一页”后，才会调用内容创作模型建立第一条状态与账本事件。

**关闭情侣守护后，还会生成角色生活吗？**

不会生成。关闭后会停止守护账本的写入、角色可选工具和手动更新的内容 API 请求；已有历史不会被删除，重新开启后才会继续。

**为什么某条对话不会显示在守护动态中？**

用户已经在当前聊天、群聊、VOOM 或通话中知道的内容不会重复展示。守护动态只展示用户未知的角色生活事件。

**为什么更新失败后没有“示例内容”？**

守护记录必须忠实保存模型实际输出。模型响应不完整或请求失败时，应用会保留原有账本并报告错误，不会用本地示例冒充真实记录。

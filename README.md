# Link

Link 是一个移动端优先的 Vue 3 + Vite + PWA 角色扮演聊天应用原型，界面参考 LINK 的 Home、VOOM 与聊天房间体验。

## 功能

- 底部主导航提供主页、VOOM、Music、Fanfic 与 Wallet；进入 Fanfic 书架及其子页面后隐藏底部导航，主页内可切换 Chats、Group、Friends 与 All 会话列表。
- Wallet 只展示当前用户的全局余额、全局购物车、全局愿望单、全局订单与收支，不再聚合所有角色账户或角色心意。角色经济、共同购物、共同愿望、礼物卡片、角色店铺和关系订单统一从对应单聊的“与 TA 的生活”进入，并按角色 ID 与 conversation ID 分开持久化。
- Shop 保留默认商品，并提供当前角色“AI 上新”：文本模型根据用户与角色资料及非空“禁忌之书”生成店铺设定、商品、价格与晒单，不读取或注入普通聊天上下文。角色选品、AI 上新与商品图均直接调用已配置的 API；请求失败时直接显示错误，不生成或返回本地降级结果。
- Shop 与当前线上单聊双向联动：关系模式自动锁定当前角色，不提供跨角色选择器；用户可把商品、愿望、角色店铺和生活记录发回该单聊，结算后订单会绑定聊天消息并可回跳原楼层。聊天操作菜单分别提供“点外卖”和“送礼物”，用户可像转账一样自行填写店铺、餐品或礼物、实付金额、送达时间、卡片与备注，付款后扣除用户 Wallet 并生成与角色订单一致的聊天卡片和关系订单；角色发送的外卖、礼物或购物订单仍写入角色账本。聊天转账在接受后同时更新用户与角色钱包，拒绝、撤销或编辑状态会幂等冲销，历史已接受转账会在载入时补齐账本。
- Fanfic 明确定义为当前用户与所选角色的原创 AU 同人作品：可从依据公开网络文学分类整理的 16 个跨频道大类、832 个不重复题材（含 256 个古言、现言、青春与幻想女频题材）、联网通用趋势标签或自定义题材开始。内置题材只保存分类与方向，不预设开局、身份、世界、冲突、关系或商业种子；策划、章节、评论和联网题材文本请求统一使用全局小剧场模型，未单独选择时跟随 API 默认模型。设置视角、连载基调、结局、篇幅与内容边界后，由模型生成封面提示词、书名、笔名、标签式简介、故事发动机和每章约 2500 字的正文，不再预先生成全书分章大纲；后续章节根据故事圣经、已发布事实、用户方向与连续性账本自然推进。同人书架在移动端每行展示三本作品。
- Fanfic 创建与续写会直接读取双方人物设定和所选角色启用的局部世界书，但提示词明确将它们限定为性格、表达、边界与世界灵感参考，不要求逐条照搬，也不把资料中的经历自动视为正文事实；聊天、记忆、其他角色资料和普通全局世界书不会进入正文。章节请求同时生成正文与 2–3 个高潮评论插入点，不提前生成评论；读者首次点击某个热点时，系统才携带该热点和附近正文单独请求评论并写入 IndexedDB，之后直接使用本地缓存。
- 单角色聊天支持“情侣守护”空间：在明确共享授权后，按角色设定、聊天记忆和时间上下文调用 API 生成覆盖过去 24 小时的完整生活行程、聊天之外的联系人消息、通知、应用使用、搜索/浏览/地图/购物足迹、相册、备忘录、闹钟/日程/订单/音乐/草稿、生活印记与心愿便利贴；内容是角色互动模拟，不读取真实设备定位、联系人或系统解锁数据。
- 同一个 conversation 支持线上聊天和线下长文本 RP 两种渲染。
- 线上私聊中，双击左侧角色头像会打开韩系 INS 风的本轮 API 记录卡，展示 Gemini Thought、Claude Thinking 或 OpenAI 兼容 reasoning 实际返回的内容，以及 MCP 服务、工具名、脱敏参数、执行状态和结果；旧消息或未返回思维内容的接口会明确显示无可用记录。双击右侧用户头像可直接触发与输入区“回复”按钮相同的角色回复。
- 在线私聊和群聊发送含 `https://` 链接的文字时，会把第一条链接即时保存为可点击分享卡片；小红书、抖音和淘宝显示独立平台样式，普通网站显示站点域名。服务端在登录会话和限流保护下读取公开网页的 Open Graph 标题、摘要与封面并异步补全卡片；抓取失败仍保留可点击的平台/域名卡片，不阻塞消息发送。网页 HTML 不会保存到聊天，外部元数据按不可信内容处理，服务端拒绝私网地址、非 HTTPS 上游和跳转到内网的链接。
- 私聊可通过邀请卡发起十五路五子棋，角色也能结合当前关系和会话主动邀请。邀请支持接受、拒绝与角色真实 API 决策；接受后进入独立棋局子页面。棋局内的用户文字、角色回复、旁白和落子对白仍写入原线上会话楼层并复用同一角色设定、世界书、记忆摘要、现实时间感知和可见历史。应用本地只负责邀请状态、棋盘合法性与胜负裁判，不包含选点、评分、伪对白或失败兜底棋力。
- 私聊支持双向拉黑、软删除和重新添加好友：普通“仅删除好友”保持原行为并保留角色资料、记忆与历史；也可经二次确认彻底删除该好友，清理其私聊/线下 RP、消息收藏、记忆、情侣空间、VOOM、主页、小剧场、专属局部世界书、Fanfic 与商城钱包关联。黑名单状态仍可点击“回复”推进关系，被拦截的消息显示红色感叹号，用户和角色都可重新发起好友验证并由对方决定是否恢复。
- 支持邀请当前账号绑定角色与多个自定义 NPC 创建群聊，也可选择一个或多个绑定角色后调用 API 搜索并加入 3–6 个模拟既有群聊。
- 群聊保存群主、成员、公告和历史消息；每条消息通过成员 ID 记录明确作者，正文中的姓名、昵称、代词和关系称谓按上下文自然保留，不做真名改写。
- 群聊角色会读取其私聊/线下 RP 的共同楼层、摘要、记忆和局部世界书；群聊事件会以隐藏上下文同步回角色私聊，保持跨会话连续性。
- 进入线下模式会切换会话模式与提示词，退出后切回线上模式。
- 用户人设、角色名称、头像、角色资料、朋友圈频率可编辑。
- Add 页支持从 PNG、JSON 角色卡或 TXT、DOC、DOCX 人设文档导入角色；文档全文进入角色资料并以文件名作为默认角色名。World Archive 支持从 JSON、TXT、DOC、DOCX 文件批量导入世界书。
- IndexedDB 本地存储用户、角色、会话、消息、VOOM、Fanfic 书籍/章节/评论/题材/生成任务、世界书和 API 设置。
- Services 的 Backup 子页面支持本地导入导出、用户自有云盘/R2 端到端加密自动备份，以及 GitHub 私有仓库备份；完整备份会压缩并保留全部生图及候选图、本地 Stickers 和自定义铃声。Android App 会把本地 ZIP 备份写入系统 `Downloads/BabyLink`，iOS App 通过系统分享面板存储文件。
- 生产服务支持 QQ 群一次性口令注册、NapCat 多群成员校验、设备管理、退群撤权和受保护安装包发布；Android App 可校验 SHA-256、包名、版本号和签名证书后调用系统覆盖安装，iOS App 可生成持续复核群资格的 AltStore/SideStore 更新源。
- 世界书分为线上全局、线下全局、局部世界书；每本世界书支持多个可单独开关的条目、绿灯关键词触发、蓝灯常驻注入和黄灯优先注入，局部世界书可绑定到角色。系统固定保留不可删除、不可停用的“禁忌之书”：非空启用条目会作为最高优先级上下文置于全站文本生成请求最前方；图片生成固定不会读取本书内容；内容全空时始终不注入，备份恢复或清空世界书数据后仍会保留空书。
- VOOM 可手动生成，也可在 AI 回复后按角色频率低频自动生成。
- PWA manifest 与 service worker 已配置，可在移动浏览器安装。
- 网站、Android APK 与 iOS IPA 共用 Stickers 本地持久缓存：导入时会先下载并压缩图片，再写入当前设备的 IndexedDB/本地媒体存储；导入完成后直接复用本地副本，不会在每次打开时重新下载源图片，旧版未缓存贴纸会在升级后后台补齐一次。Stickers 页顶部的分享按钮可选择单个、多个或全部分组，导出携带分组和图片数据的 PNG 分享包；接收方在同页点击“+”并选择该 PNG 即可导入使用。
- Themes 的“字体”分栏会在导入字体文件或 CSS/字体链接时将字体资源持久缓存到本机，后续冷启动直接恢复已应用字体，不再重复访问字体源站；“全局”分栏支持整体缩放、仅限 iOS 网页/PWA 的底栏位置微调、持久化全屏开关和全站 CSS 主题预设。底栏微调不会改变 Android 网页、Android APK 或 iOS IPA 的安全区布局。全站样式覆盖所有子页面、表单、卡片、导航、弹窗与浮层，且与线上/线下样式一致支持代码编辑、PNG 导入导出和分享。Android/iOS App 使用系统文件选择器导入主题 PNG，并通过系统分享面板导出。
- Services 以韩系 ins 风入口集中管理 Keep Alive、Update、Backup、QQ Access 和 Data，并通过独立子页面承载各自功能。
- 聊天 Stickers 面板作为输入区下方的真实页面布局打开，消息列表会像软键盘出现时一样自动缩小；点击输入框会关闭面板并直接进入输入状态。
- Ringtones 通过底栏分开管理全局与角色铃声，Backup 通过底栏分开管理本地、免费个人云盘与 GitHub 备份；Data 会汇总业务数据、启动偏好、媒体文件库与离线资源，提供浏览器持久化保护、App 临时文件清理、媒体健康校验和分级数据清理。业务分区清理前会确认；钱包与商店使用“重置”语义，后续访问时可按需重建示例资料。
- 网站与 App 在授权缓存有效时立即挂载页面壳，并保存轻量启动快照；首次打开完成后，后续冷启动会先显示缓存的账号与会话，再在后台恢复完整 IndexedDB 数据。PWA 会预缓存全部构建资源，Android/iOS App 直接从主页启动，不再在每次打开时执行全部页面预载。
- 已开启的线上私聊主动消息由全站根调度器统一检查，不再要求停留在对应聊天页；页面可见性变化、BFCache 恢复、网络恢复和 Capacitor App Resume 时会立即补检，60 秒定时器仅作辅助。Android 开启 Keep Alive 后使用原生前台服务与可选 CPU Wake Lock，并建议允许忽略电池优化；浏览器、PWA 与 iOS 后台均为尽力运行，不保证锁屏期间准时，页面或 App 被强制关闭后不会继续生成消息。
- 角色消息通知完整展示本轮全部消息；Android App 使用单侧角色头像显示社交通知。聊天与 VOOM 图片可保存到系统相册；全站/线上/线下样式和主页主题 PNG 在 Android/iOS App 中通过系统分享面板导出。

## API

设置页的 API 分栏可以配置 OpenAI 兼容文本模型供应商：

- `API Url`：供应商根地址，例如 `https://api.openai.com/v1` 或 `https://api.example.com/v1`。
- `API 路径`：聊天补全路径，通常是 `/chat/completions`。
- `API Key`：请求时作为 Bearer token 发送。
- `Model`：在“选择模型”里同步或手动选择后传给接口。
- `流式回复`：默认关闭以保持旧接口兼容；“自动尝试”会请求 SSE 流并在供应商不支持时回退为普通 JSON 响应，“强制开启”仅用于已确认支持流式的接口。

本地 `npm run dev` 与 `npm run preview` 会把远端文本模型请求优先转发到同源代理，避免浏览器直连 OpenAI 兼容网关时被 CORS 拦截。如果部署到纯静态站点，请使用支持浏览器跨域的网关，或自行部署同源后端代理。

如果不填写供应商，应用会提示先配置 API 模型，方便在发起真实回复前检查设置。

五子棋与线上聊天共用同一套供应商和角色级线上模型覆盖。用户邀请角色时，角色会像处理语音通话一样通过同一线上回复决定接受或拒绝；普通线上回复也允许角色主动发出五子棋邀请。棋局页面支持先发送多条桌边消息再请求角色回复；会话启用旁白时，普通棋局回复及真实落子 API 都可返回角色侧旁白。断网、超时、鉴权失败、非 JSON 或非法坐标都会显示为棋局错误，角色不会在本地自动补下一手。刷新时真正处于请求中的角色回合会标记为已中断，由用户手动决定是否再次调用 API。

### MCP 与平台搜索

- 内置“真实系统能力”MCP 的 `search_web` 不需要地址、密钥或部署配置：默认聚合 Bing 中国、百度和搜狗的公开网页结果并去重，也可由角色指定单个引擎。搜索仅返回公开标题、摘要、来源和链接；百度、搜狗页面结构或风控导致不可用时，默认聚合会保留其余引擎结果。`get_live_news` 优先使用 Bing 中国新闻，查询失败时才回退 GDELT 全球新闻索引。
- 内置“系统通知 MCP · 角色专用”只提供通知授权状态与近期系统通知摘要查询，默认不全局应用；在聊天设置中为指定角色开启“角色独立配置”后再单独勾选。它只使用 Android 通知使用权在本机保存的摘要，不会调用 QQ Bridge 历史消息工具，也不能清空通知或更改系统授权。
- 在 Services → MCP Studio → 连接 → AI 平台搜索中，可以分别添加淘宝商品、抖音视频和小红书笔记搜索 MCP。它们与“小红书电脑 Bridge”是不同连接，不会用打开 App、Deep Link 或普通网页搜索冒充平台搜索。
- BabyLink 接受公开的 HTTPS MCP Streamable HTTP 地址，也允许 `http://localhost`、`http://127.0.0.1` 和 `http://[::1]` 连接同一台设备上的 MCP；本机服务需允许 BabyLink 来源的 CORS 请求。手机中的回环地址指手机自身，不能借此访问电脑；局域网地址和本地 stdio 仍不能直接使用，跨设备自托管服务必须通过 HTTPS 反向代理增加访问鉴权。
- 淘宝模板参考 [liuliang520530/taoke-mcp](https://github.com/liuliang520530/taoke-mcp) 的淘宝联盟物料搜索。该社区实现需要淘宝联盟 `TAOBAO_PID`、`TAOBAO_SESSION`，并依赖 `ENV_URL`、`ENV_SECRET` 对应的第三方配置服务；部署者需要自行审计并把全部凭据保存在 MCP 服务端。
- 抖音模板参考 [pazwusimple-netizen/douyin-mcp](https://github.com/pazwusimple-netizen/douyin-mcp) 的 `search_videos`。原仓库默认使用本地 stdio，并通过 Cookie、签名计算及浏览器回退访问真实抖音数据；接入前需要自行改造或包装为 Streamable HTTP，同机可用回环 HTTP，跨设备必须使用带鉴权的 HTTPS，Cookie 不得填写到 BabyLink。
- 小红书模板参考 [xpzouying/xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp) 的只读 `search_feeds`。该实现原生提供 `http://localhost:18060/mcp`，需要先完成扫码登录；同机浏览器可直接填写该地址，跨设备使用时应在 `/mcp` 前增加 HTTPS 和反向代理鉴权，Cookie 只保存在服务端。
- 平台按钮只创建对应的连接模板，不会自行提供搜索能力。填写地址后，自动检测必须成功发现淘宝物料搜索、抖音 `search_videos` 或小红书 `search_feeds` 等真实工具；一个 MCP 若同时提供三类工具，只需添加一个自定义连接。
- 当前没有把第三方社区项目标记成淘宝、抖音或小红书官方 MCP。平台模板默认使用“只浏览”权限；连接发现工具后仍可逐工具关闭，写工具不会在只读策略下提供给角色。
- Services → 运营中心将角色账号和用户账号严格分开：角色账号绑定角色自己的平台身份，才可进入点赞、发布、评论、私信和分享任务；用户账号仅授权指定角色读取小红书/抖音资料、作品、内容与评论，绝不作为角色写入身份。账号密码、Cookie、令牌不会保存到 BabyLink 或导出备份。
- 外部写入默认逐条确认。只有用户明确切换为“仅白名单内可自动执行”后，且同时满足收件人白名单、静默时段、敏感词、每小时/每日上限和 Bridge 的平台侧守卫，前台恢复时才会执行到期任务；浏览器/PWA 不保证后台定时执行。聊天模型不能绕过运营中心直接调用写工具。
- 小红书 Bridge 可经适配器读取账号资料、作品、笔记与评论，并执行点赞、发布、评论、草稿、排程和适配器支持的私信；QQ 使用 OneBot 的私聊/群消息；抖音写入需要用户自己的本机适配器实际提供点赞、发布、评论或私信工具。系统分享会打开用户当前设备的分享面板，绝不自动选择收件 App 或联系人。
- 搜索结果的链接、图片、价格、作者和来源从 MCP 原始结构化响应中清洗并单独持久化，不由文本模型重新生成。聊天卡片只接受 `http:`/`https:` URL，不渲染外部 HTML，点击后直接打开真实平台原始链接。
- 页面进入后台时不会主动取消正在执行的 MCP 请求；后台冻结时间不计入客户端活动超时。若会话明确失效会重建连接，只读搜索可在安全条件下重试，结果不确定的写操作不会自动重复。
- 线上聊天的每轮回复由同一次角色模型请求同时生成聊天消息与 MCP 行动决定：角色会综合人设、记忆、对话摘要、近期消息与当前情境，自行决定是否调用 MCP、调用哪些已启用工具及参数。不调用工具时直接发送这次生成的消息；调用工具时会先发送自然的行动前消息，再展示工具过程，并依据真实结果继续回复。MCP 的总开关、服务器开关、角色绑定、权限策略和单工具开关是唯一权限边界；处于“浏览并操作”策略的工具可由角色自行执行写入操作，不另设确认或自主调用开关。

### Fanfic

- 创建同人文前必须为当前用户和所选角色填写真名；昵称不会作为正文双主角名兜底。
- 文本生成使用当前配置的 OpenAI 兼容模型。创建与续写会把双方人物设定和角色绑定的启用局部世界书直接作为非强制参考，同时结合原创故事圣经、已发布章节事实、用户选择与连续性账本继续写正文。
- 每章正文在模型返回并完成必要的格式规范化后直接保存，不会因与人物设定或局部世界书存在文字重合而拦截、重写或报错。评论阶段可读取同账号绑定角色的真名、签名与角色设定，但这些资料不会进入正文提示词；聊天、记忆和普通世界书不会提供给评论模型，非空“禁忌之书”仍作为全站优先上下文读取。
- 书名、笔名、简介、故事圣经、正文、趋势题材和按需热点评论均由模型生成；章节发布只要求存在可展示的正文，缺少章名时自动使用章节序号，摘要、连续性、高潮评论点与下一章方向缺失时会安全规范化，不再因段数、字数或附加字段数量让正文失败。
- “联网趋势”调用受保护的 `/api/fanfic/trends`，服务端仅从公开搜索结果提取固定通用题材标签，不下载小说正文；网络不可用时自动使用内置趋势标签。
- AI 封面使用图片设置中当前选中的图片供应商；未配置或生成失败时使用可离线显示的程序 SVG 封面。

### 群聊

- 在 Add 页切换到“创建群聊”，可以邀请当前账号绑定角色，并添加多个带真名、群昵称、头像和角色设定的自定义 NPC。
- 在 Add 页切换到“加入群组”，选择角色后点击“查找群聊”。搜索会调用当前文本 API，并读取所选角色的设定、局部世界书、线上/线下会话与记忆。
- 候选结果展示群名、成员、群主、公告和最近消息；点击“加入”后才会写入 IndexedDB。
- 群聊输入区的“发送”只发送用户消息，“回复”会在发送后调用 API，由群内合适的一个或多个成员自然回复。
- 群聊支持引用、撤回、@成员、Stickers、本地/描述图片、录音/文字语音；长按消息可复制、引用、撤回或仅删除本地记录。
- 加号菜单支持邀请当前账号绑定的角色、重新生成上一轮群回复、退出群聊和删除群聊；受邀角色会带着已有设定与连续记忆成为真实群成员。
- 退出后会保留群聊与历史，可继续调用 API 旁观群成员聊天、使用固定匿名小号发言，或重新申请加入并由 AI 扮演的群主/管理员按群关系通过或拒绝。
- 群主和管理员可修改群名与公告；所有在群成员都可通过 URL 或本地上传裁剪修改群头像，修改后自动保存。
- 群设置可绑定多个 Stickers 分组，群内任何 AI 成员都可从绑定分组中发送 Stickers。
- 邀请成员、退出、申请、审批及资料变更都会写入群聊系统事件并同步角色上下文。
- 群资料可分别开启主动群消息并设置频率。
- 群聊回复可以由 AI 判断是否让某位已有角色转到线上私聊主动联系用户，群事件会先写入该角色的连续上下文。

## 数据备份

设置页底部的“备份”分栏提供本地、用户自有云盘和 GitHub 三种数据保护方式：

- `导出备份`：生成当前 IndexedDB 的 ZIP 快照；Android 写入系统 `Downloads/BabyLink`，iOS 在“文件”面板确认保存，支持文件句柄的网站会直接写入用户选择的位置。
- `导入备份`：选择此前导出的 ZIP 或旧版 JSON 文件并替换当前本地数据。
- `免费个人云盘`：Google Drive、OneDrive 和 Dropbox 使用账号自带免费空间；完成官方 OAuth 授权后，可以选择立即备份、应用运行时自动备份或导入云盘备份，不要求用户付费或部署服务。
- `云盘安全恢复`：首次授权不会立即覆盖云盘同名文件；首次使用可点“立即备份”，新设备则先填写原恢复密钥，再点“导入云盘备份”。
- `云盘自动备份`：用户主动开启后，应用运行时按设定间隔检查并更新端到端加密备份；新设备导入旧备份前不会默认开启。
- `恢复密钥`：密钥仅保存在当前设备并从所有导出快照中清除，跨设备恢复前必须由用户自行保存和填写。
- `GitHub 登录`：配置 Cloudflare Worker 后会打开 GitHub OAuth 授权页，授权完成后自动回到 LINK。
- `GitHub 自动备份`：OAuth 登录成功后会自动创建私有仓库、开启自动备份并完成首次备份；也可以手动填写 token 后连接账号。
- `导入 GitHub 备份`：连接 GitHub 后，可直接把私有仓库里的备份文件拉回本地并覆盖当前 LINK 数据。
- `自动检测恢复`：登录 GitHub 后如果检测到仓库里已有较新的备份，会提示是否恢复到当前设备，避免先覆盖云端旧数据。
- `历史备份列表`：设置页会显示最近三次 GitHub 备份记录，可按某一个历史版本恢复。
- `备份可视化`：设置页会显示最近同步状态、手动/自动备份进度条，以及导入恢复阶段进度。

GitHub token 需要具备创建私有仓库和写入仓库内容的权限。所有导出快照会清空 GitHub token、云盘 OAuth Token、旧版 R2 连接密钥和恢复密钥。备份内容、云盘 Token 与恢复密钥只存在于当前设备和用户选择的第三方存储，LINK 服务端不接收、不存储、不转发这些数据。

### 云盘 OAuth 配置

生产维护者需要在部署环境填写 `VITE_GOOGLE_DRIVE_CLIENT_ID`、`VITE_ONEDRIVE_CLIENT_ID` 或 `VITE_DROPBOX_APP_KEY`；这些是公开 OAuth 应用标识，不是用户配置，也不包含用户数据。Docker 构建会从 `deploy/.env` 自动注入。三个 OAuth 应用都只需要配置当前 PWA 的回调地址：

`https://<你的域名>/services/backup/oauth/callback`

OAuth 令牌只保存在当前设备的 IndexedDB；应用关闭后，浏览器不会保证定时任务继续运行，重新打开或回到前台时会补做备份。

## QQ 群访问控制

生产服务使用 Fastify、PostgreSQL 与 NapCat OneBot 11 反向 WebSocket：

- 用户输入 QQ 后获得 5 分钟一次性口令，并必须用同一 QQ 在任一授权群发送绑定命令。
- 每台新设备独立验证，默认每个 QQ 最多三台设备；用户可在备份设置页移除设备。
- 用户可在任一授权群发送 `/link 清空设备`，立即撤销自己 QQ 的全部设备和登录会话；已移除设备不再显示在 QQ 访问账号列表中。
- NapCat 监听进群/退群事件并定时全量同步多个授权群；不再属于任何授权群的账号会被撤销会话。
- 应用只在服务器保存最少账号元数据，聊天和角色数据继续保存在用户本地。

### GitHub OAuth Worker

项目内置 `workers/github-oauth`，用于安全保存 GitHub OAuth secret 并把授权结果回传给 PWA。

1. 在 GitHub 创建 OAuth App：
	- `Authorization callback URL` 填 `https://<你的 Worker 域名>/github/callback`。
	- 记录 `Client ID` 和 `Client Secret`。
2. 把 `workers/github-oauth/wrangler.toml` 里的 `APP_ORIGIN` 改成你的 PWA 域名；本地开发可保留 `http://localhost:5173`。
3. 部署 Worker：

```bash
cd workers/github-oauth
npx wrangler secret put GITHUB_CLIENT_ID
npx wrangler secret put GITHUB_CLIENT_SECRET
npx wrangler secret put OAUTH_STATE_SECRET
npx wrangler deploy
```

4. 在前端环境变量里配置 Worker URL：

```bash
VITE_GITHUB_OAUTH_WORKER_URL=https://link-github-oauth.<your-subdomain>.workers.dev
```

配置后，设置页的“GitHub 登录”会走 Worker OAuth；未配置时仍会退回 GitHub token 创建页。

### 全屏显示

Themes 的“全屏显示”首次默认开启，用户明确关闭后会保留关闭偏好。应用会按运行环境选择实现：Android APK 使用原生 immersive/WindowInsets，iOS IPA 使用原生状态栏控制，PWA 以 `standalone` 模式启动，并在用户开启开关时使用浏览器 Fullscreen API；普通网站同样需要浏览器授权。普通网页无法绕过浏览器或手机系统权限；iOS Safari 以及 iOS 主屏 PWA 不允许网页隐藏电池/网络状态栏，只能使用半透明安全区显示。修改原生全屏代码后需要重新执行 `npx cap copy` 并重新构建 APK/IPA；已安装的旧版全屏 PWA 需关闭后重新打开，若仍未应用新清单则重新安装。
